# 🎬 LitrHelperBot

Инлайн-бот Telegram: качает **TikTok без водяного знака** и **музыку из SoundCloud** прямо в тот чат, где ты написал запрос.

## Что умеет

| Что пишешь в любом чате | Что получаешь |
|---|---|
| `@LitrHelperBot ссылка_на_тикток` | кнопка **«⬇️ Скачать видео»** → видео без водяного знака |
| `@LitrHelperBot ссылка_на_саундклауд` | кнопка **«⬇️ Скачать музыку»** → аудиофайл трека |
| `@LitrHelperBot Артист - Название песни` | список найденных треков SoundCloud, каждый со своей кнопкой |

Бот не пишет отдельных сообщений: он показывает inline-сообщение с кнопкой, а по нажатию **заменяет его в чате** на готовый файл. Никакого мусора в чате.

> **Один раз напиши боту `/start` в личке — без этого музыку не пришлёт.** Видео
> работает и так, а трек Telegram может приложить к сообщению только через личный
> чат (см. «Как файл попадает в чат»).

## Установка

1. Открой [@BotFather](https://t.me/BotFather), создай бота → получи токен.
2. Включи инлайн-режим: `/setinline` → выбери бота → впиши описание (например `Скачать музыку и видео`) → **Done**.
   Без этого шага бот не будет работать в инлайне.
3. Запусти `install.bat` (создаст `.venv` и поставит библиотеки).
4. Скопируй `.env.example` в `.env` и впиши `BOT_TOKEN=123456:AA...`.
5. Запусти `start.bat`.

Ручной вариант:

```bat
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python bot.py
```

## Проверка что всё живо

* В личке с ботом: `/start`, `/help`, `/stats` (статистика + сколько ОЗУ ест процесс).
* Если в логе `Инлайн-режим ВЫКЛЮЧЕН!` — снова к `@BotFather` → `/setinline`.

## Как файл попадает в чат (важно)

Telegram **запрещает загружать новые файлы в инлайн-сообщения**. Прямо из доки
`editMessageMedia`:

> When an inline message is edited, a new file can't be uploaded; use a previously
> uploaded file via its file_id or specify a URL.

Поэтому бот идёт по трём шагам, пока не сработает:

1. **Прямая ссылка — только для видео.** Бот получает ссылку на файл (tikwm)
   и отдаёт её в `editMessageMedia`. Файл скачивает сам Telegram — бот ничего
   не качает и не грузит. Это самый быстрый путь.
2. **`file_id`.** Бот качает файл, кладёт его в личный чат пользователя,
   достаёт из ответа `file_id`, удаляет временное сообщение и уже этим
   `file_id` заменяет инлайн-сообщение. Нужен личный чат — то есть один раз
   написать боту `/start`.
3. **Текст.** Если и это не вышло, бот честно пишет, что произошло, и даёт
   кнопку «открыть бота».

### Почему музыка всегда идёт через `file_id`

Проверено на живых треках: mp3 на SoundCloud лежат по адресам вида
`cf-media.sndcdn.com/s9KBLvMpTz3d.128.mp3` — имя файла там случайный хеш.
Когда Telegram скачивает аудио **по ссылке**, он показывает название из тегов
файла и **игнорирует** переданные `title`/`performer` — в плеере выходит
`s9KBLvMpTz3d`. Поэтому аудио бот качает сам и отправляет через `sendAudio`,
где название и исполнитель задаёт бот: плеер показывает
`Артист — Название`.

Видео наоборот оставляем на прямой ссылке: у mp4 нет метаданных, которые
Telegram перетирает, а лишняя загрузка через бота только жрёт время и память.

## Почему он не жрёт оперативку

Замер на этой машине (Python 3.10, x64):

| Вариант | ОЗУ на простое |
|---|---|
| пустой интерпретатор | 14.9 МБ |
| **этот бот (aiohttp + `src/tg.py`)** | **31.9 МБ** |
| тот же бот на aiogram | 169.6 МБ |

**aiogram съедает ~138 МБ только на импорте** (сотни pydantic-моделей в `aiogram.types`).
Поэтому Telegram-слой написан на голом aiohttp: в нём ровно те 7 методов Bot API,
которые нужны боту. Экономия — в 5.3 раза.

Что ещё сделано:

* Видео в основном пути **вообще не проходит через бота** — Telegram забирает его
  по ссылке сам. Ни диска, ни трафика через бота, ни памяти под файл.
  (Музыку приходится качать боту — иначе Telegram покажет случайное имя файла,
  см. «Почему музыка всегда идёт через `file_id`».)
* `yt-dlp` запускается **отдельным процессом** (`sys.executable -m yt_dlp`), а не импортируется в бота:
  тяжёлые библиотеки живут только во время скачивания, а главный поток не блокируется.
* Один общий `aiohttp.ClientSession` на весь бот (`TCPConnector(limit=8)`, DNS-кэш).
* Не больше `MAX_CONCURRENT_DOWNLOADS` загрузок одновременно (по умолчанию 2) и потолок в
  16 параллельных апдейтов — память не растёт при флуде.
* Кэш кнопок — обычный `dict` с TTL (15 мин), максимум 600 записей, чистится по таймеру.
* Временные файлы удаляются сразу после отправки и при старте бота.
* `gc.freeze()` после старта, `gc.collect()` после каждой загрузки.
* Нет БД, ORM и веб-фреймворков.

## Настройки (`.env`)

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `BOT_TOKEN` | — | токен от BotFather (обязательно) |
| `MAX_CONCURRENT_DOWNLOADS` | `2` | сколько файлов качать одновременно |
| `MAX_UPLOAD_MB` | `49` | лимит размера файла (Telegram не примет больше 50) |
| `CONVERT_TO_MP3` | `1` | конвертация треков в mp3 (нужен ffmpeg в PATH) |
| `CACHE_TTL` | `900` | сколько секунд «живёт» нажатая кнопка |
| `MAX_KNOWN_CHATS` | `2000` | сколько личных чатов помним (нужны для `file_id`) |
| `SEARCH_LIMIT` | `8` | треков в выдаче SoundCloud |
| `LOG_LEVEL` | `INFO` | `DEBUG` — подробный лог |
| `TELEGRAM_PROXY` | — | прокси для `api.telegram.org`, напр. `http://127.0.0.1:8080` |
| `TELEGRAM_CA_BUNDLE` | — | файл `.pem` с CA, которым подписан перехват SSL |
| `VERIFY_TELEGRAM_SSL` | `1` | `0` — не проверять сертификат Telegram |

## Если бот не подключается к Telegram

На части сетей (DPI, антивирус, корпоративный VPN, блокировки) трафик к
`api.telegram.org` перехватывают и подменяют сертификат. Бот это обнаружит сам:

```
WARNING | SSL api.telegram.org не проходит проверку - похоже, трафик перехватывают
WARNING | Повторяю подключение без проверки сертификата ...
```

и продолжит работу. Чтобы вернуть нормальную проверку сертификата, узнай CA
перехватчика и укажи его файл:

```bat
.venv\Scripts\python -m pip install certifi
set TELEGRAM_CA_BUNDLE=ca.pem     % где ca.pem - файл сертификата с компьютера %
```

Если Telegram заблокирован на уровне сети — укажи прокси: `TELEGRAM_PROXY=http://127.0.0.1:8080`.

## Полезно знать

* **ffmpeg** (необязательно, но лучше): поставь в PATH, и треки будут приходить в `.mp3`.
  Без него придёт исходный файл SoundCloud (обычно `.m4a`/`.opus` — Telegram их играет).
  Поставить одной командой: `winget install --id Gyan.FFmpeg -e` (после перезапуска консоли).
* Скачивание видео делают бесплатные публичные API (tikwm.com). Если они перестанут работать —
  в логе будет `tikwm ... вернул ...`, а в чате сообщение об ошибке.
* Обновлять выгрузчик раз в пару недель: `.venv\Scripts\python -m pip install -U yt-dlp`.
* Права на скачиваемый контент — на тебе; бот для личного использования.
